# Event Ops Systems Sprint

## Promise

Turn one fragmented event-operations workflow into a working, maintainable Airtable system in one fixed-scope sprint.

This is for event venues, production teams, conference operators, and small agencies currently re-entering the same information across spreadsheets, inboxes, forms, calendars, and chat threads.

## Fixed scope — $950

- A 60-minute workflow and failure-point review
- A current-state map showing duplicate entry, unclear ownership, and broken handoffs
- One future-state workflow covering a single operational job
- An Airtable MVP with up to five connected tables
- Up to two native Airtable automations
- One operator-facing interface or dashboard
- Test data and a written acceptance checklist
- Plain-language operating notes and a 45-minute handoff
- One revision round within seven days of handoff

Examples of an appropriate first workflow include speaker and session operations, venue enquiry-to-confirmation, vendor onboarding and approvals, crew and equipment assignments, or event closeout and follow-up.

## Boundaries

The sprint does not include paid third-party software, custom mobile applications, unrestricted API integrations, historical data cleanup beyond an agreed sample, payroll, accounting advice, public ticketing, or ongoing support. Anything outside scope receives a separate proposal only after the sprint proves value.

## Buyer outcome

The buyer leaves with a working system—not a slide deck—plus enough documentation to operate and change it without permanent consultant dependence.

If an official Airtable template or an existing vertical product already solves the agreed workflow, the sprint should recommend that route and limit paid work to fit assessment, setup, testing, and adoption. Custom configuration is not valuable by itself.

## Qualification

A good fit has a repeated workflow, a named owner, existing sample records, and a visible cost from re-entry, missed handoffs, unclear status, or stale reports. A poor fit wants an all-in-one platform, cannot name the first workflow, or expects integrations without granting access and testing time.

## Acceptance criteria

The sprint is complete when the agreed sample records move through the workflow, the two automations pass their test cases, the operator view answers the agreed status questions, and the buyer receives the handoff materials.

## Validation positioning

This offer is intentionally smaller than a typical $2,500+ custom build. The purpose is to prove one workflow, reduce implementation risk, and create evidence for a larger engagement only when the MVP is actually used.
